# NL_2026

Индивидуальная работа по курсу «Новые языки программирования».

Студент группы 5030102/30401 Некрасов Леонид Сергеевич

20 программ на 20 разных языках программирования. Пять тем, на каждую тему — по 4 программы. Для реализации задач используются стандартные библиотеки языков программирования.

## Порядок работы

Каждая задача выполняется в отдельной ветке. Имя ветки: `<номер темы>_task_<номер задачи>_<язык>`.

Исходный код располагается в соответствующей директории. Для каждой задачи предусматривается отдельный README с постановкой задачи, инструкцией по запуску и ссылкой на видеопрезентацию.

## Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык | Ветка |
|---|---|---|---|
| 1 | Параллельное построение гистограммы байтов | Rust | `1_task_1_rust` |
| 2 | Параллельное вычисление префиксных сумм | Kotlin | `1_task_2_kotlin` |
| 3 | Параллельное численное интегрирование методом трапеций | Julia | `1_task_3_julia` |
| 4 | Параллельное кодирование методом RLE | D | `1_task_4_d` |

**1.1 Параллельное построение гистограммы байтов (Rust).** Массив байтов разделяется на части, каждая из которых обрабатывается отдельным потоком с использованием `std::thread`. Каждый поток формирует локальную гистограмму из 256 элементов. После завершения потоков результаты объединяются. Сравниваются результаты и время выполнения последовательной и параллельной реализаций.

**1.2 Параллельное вычисление префиксных сумм (Kotlin).** Исходный массив разделяется на блоки, для каждого из которых в отдельном потоке вычисляются локальные префиксные суммы. После определения сумм предыдущих блоков выполняется параллельная корректировка элементов. Результат сравнивается с последовательным вычислением.

**1.3 Параллельное численное интегрирование методом трапеций (Julia).** Интервал интегрирования разбивается на участки, вычисления на которых выполняются параллельно с использованием `Threads.@threads`. Частичные результаты объединяются в итоговое значение интеграла. Сравниваются точность и время выполнения последовательного и параллельного алгоритмов.

**1.4 Параллельное кодирование методом RLE (D).** Входная последовательность символов разделяется на блоки, каждый из которых независимо кодируется методом Run-Length Encoding с использованием `std.parallelism`. После завершения обработки соседние серии одинаковых символов на границах блоков объединяются. Проверяется возможность восстановления исходной последовательности.

## Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык | Ветка |
|---|---|---|---|
| 1 | Генерация правильных скобочных последовательностей (рекурсия) | Haskell | `2_task_1_haskell` |
| 2 | Раскраска графа перебором с возвратом (рекурсия) | Prolog | `2_task_2_prolog` |
| 3 | Топологическая сортировка графа алгоритмом Кана | OCaml | `2_task_3_ocaml` |
| 4 | Поиск наибольшей возрастающей подпоследовательности | F# | `2_task_4_fsharp` |

**2.1 Генерация правильных скобочных последовательностей (Haskell).** Для заданного числа пар скобок рекурсивно строятся все допустимые скобочные последовательности. На каждом шаге проверяется возможность добавления открывающей или закрывающей скобки. Выводятся полученные последовательности и их количество.

**2.2 Раскраска графа перебором с возвратом (Prolog).** Неориентированный граф задаётся списком рёбер. Рекурсивный алгоритм назначает каждой вершине один из заданных цветов, проверяя отсутствие конфликтов между смежными вершинами. При невозможности назначения выполняется возврат к предыдущему состоянию. Выводится допустимая раскраска либо сообщение об отсутствии решения.

**2.3 Топологическая сортировка графа алгоритмом Кана (OCaml).** Ориентированный граф задаётся списком вершин и рёбер. Для каждой вершины вычисляется входная степень. Вершины с нулевой входной степенью последовательно добавляются в результат с обновлением степеней соседних вершин. При наличии цикла программа сообщает о невозможности топологической сортировки.

**2.4 Поиск наибольшей возрастающей подпоследовательности (F#).** Методом динамического программирования для каждого элемента массива определяется длина наибольшей возрастающей подпоследовательности, заканчивающейся этим элементом. С помощью массива предшественников восстанавливается сама подпоследовательность. Выводятся её длина и элементы.

## Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык | Ветка |
|---|---|---|---|
| 1 | Построчное объединение нескольких текстовых файлов | Lua | `3_task_1_lua` |
| 2 | Поиск строк в файле по регулярному выражению с контекстом | Perl | `3_task_2_perl` |
| 3 | Работа с бинарным файлом записей фиксированной длины | Nim | `3_task_3_nim` |
| 4 | Определение и преобразование форматов окончания строк | Ruby | `3_task_4_ruby` |

**3.1 Построчное объединение нескольких текстовых файлов (Lua).** Пользователь вводит имена исходных файлов и имя результирующего файла. Программа последовательно читает по одной строке из каждого файла и записывает их в выходной файл. Поддерживается обработка файлов различной длины и вывод количества обработанных строк.

**3.2 Поиск строк в файле по регулярному выражению с контекстом (Perl).** Из консоли вводятся путь к файлу, регулярное выражение и количество строк контекста. Программа выполняет построчное чтение файла, находит совпадения и выводит номера найденных строк вместе с предшествующими и последующими строками. Результат сохраняется в отдельный файл.

**3.3 Работа с бинарным файлом записей фиксированной длины (Nim).** Реализуются создание бинарного файла, добавление записей, чтение и изменение записи по её порядковому номеру. Каждая запись состоит из нескольких целочисленных полей фиксированного размера. Доступ к произвольной записи осуществляется посредством вычисления смещения в файле без чтения предыдущих записей.

**3.4 Определение и преобразование форматов окончания строк (Ruby).** Программа читает файл в бинарном режиме, определяет количество окончаний строк типов LF, CRLF и CR. Пользователь выбирает результирующий формат. Программа нормализует окончания строк, сохраняет содержимое в новый файл и выводит статистику выполненных преобразований.

## Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык | Ветка |
|---|---|---|---|
| 1 | TCP-сервер синхронизации клиентов по барьеру | Elixir | `4_task_1_elixir` |
| 2 | UDP-сервер вычисления контрольных сумм | Erlang | `4_task_2_erlang` |
| 3 | TCP-сервер проверки скобочных конструкций | Groovy | `4_task_3_groovy` |
| 4 | Передача бинарных файлов по TCP | Scala | `4_task_4_scala` |

**4.1 TCP-сервер синхронизации клиентов по барьеру (Elixir).** Сервер принимает подключения нескольких клиентов с использованием `:gen_tcp`. Каждый клиент отправляет сообщение о готовности. После получения сообщений от заданного количества клиентов сервер разрешает им продолжить выполнение посредством отправки общего сигнала. После завершения цикла состояние барьера сбрасывается.

**4.2 UDP-сервер вычисления контрольных сумм (Erlang).** Клиент отправляет серверу датаграмму, содержащую данные. Сервер с использованием `gen_udp` принимает сообщение, вычисляет контрольную сумму CRC32 и возвращает её клиенту. Клиент сравнивает полученное значение с локально вычисленной контрольной суммой. Предусматривается обработка тайм-аута ожидания ответа.

**4.3 TCP-сервер проверки скобочных конструкций (Groovy).** Сервер принимает от клиента текстовую последовательность, содержащую круглые, квадратные и фигурные скобки. С помощью стека проверяется корректность их вложенности. Клиенту возвращается результат проверки, а при обнаружении ошибки — позиция некорректной скобки. Взаимодействие реализуется через `Socket` и `ServerSocket`.

**4.4 Передача бинарных файлов по TCP (Scala).** Клиент устанавливает соединение с сервером и отправляет имя файла, его размер и содержимое. Сервер принимает данные блоками, записывает их в файл и проверяет соответствие полученного количества байтов заявленному размеру. После завершения передачи клиенту отправляется подтверждение либо сообщение об ошибке.

## Тема 5. Конвертация данных из одного формата в другой

Папка: `5_convert/`

| № | Задача | Язык | Ветка |
|---|---|---|---|
| 1 | Преобразование изображений PGM в PBM | Swift | `5_task_1_swift` |
| 2 | Преобразование списка смежности графа в формат DOT | Clojure | `5_task_2_clojure` |
| 3 | Преобразование постфиксной записи выражений в префиксную | Scheme | `5_task_3_scheme` |
| 4 | Преобразование последовательностей FASTA в TSV | Common Lisp | `5_task_4_lisp` |

**5.1 Преобразование изображений PGM в PBM (Swift).** Программа разбирает текстовый формат изображения PGM (P2), включая заголовок, размеры и значения яркости пикселей. По заданному порогу яркости каждый пиксель преобразуется в чёрный или белый. Полученное изображение сохраняется в формате PBM (P1).

**5.2 Преобразование списка смежности графа в формат DOT (Clojure).** Программа читает текстовый файл, содержащий список смежности графа. Из исходных данных формируются вершины и рёбра, устраняются повторяющиеся рёбра неориентированного графа. Результат сохраняется в формате DOT, пригодном для визуализации графа.

**5.3 Преобразование постфиксной записи выражений в префиксную (Scheme).** Арифметическое выражение в постфиксной записи разбивается на операнды и операторы. С использованием стека формируется вложенная структура выражения, которая затем выводится в префиксной форме. Поддерживаются основные арифметические операции и обработка некорректных выражений.

**5.4 Преобразование последовательностей FASTA в TSV (Common Lisp).** Программа разбирает текстовый файл формата FASTA, выделяя заголовки записей и соответствующие последовательности. Многострочные последовательности объединяются в одну строку. Результат сохраняется в TSV-файл со столбцами идентификатора, последовательности и её длины.
